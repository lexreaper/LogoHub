# Информационная система центра логопедии

Учебный проект по дисциплине «Технологии сетевого программирования».

Система предназначена для хранения данных пациентов и логопедов, учёта специализаций, записи на приём и ведения истории посещений.

| Технология | Назначение |
| --- | --- |
| Python | Язык программирования |
| PostgreSQL | Реляционная база данных |
| SQLAlchemy | ORM и работа с БД |
| FastAPI | REST API |
| Pydantic | Валидация данных и DTO |
| Uvicorn | ASGI-сервер |
| Nginx | Обратный прокси-сервер |
| JWT (HS256) | Аутентификация пользователей |
| Argon2 | Хеширование паролей |
| Postman | Проверка HTTP-запросов |
| gRPC | Взаимодействие между FastAPI и сервисом подбора |
| Protocol Buffers | Описание структуры сообщений и сериализация данных |

## Лабораторная работа №0 — Проектирование информационной системы

Выбрана предметная область — центр логопедии. Определены роли пользователей, функциональные требования и сценарии работы. Спроектированы архитектура приложения и схема базы данных.

- Пациент — просмотр логопедов, запись на приём и просмотр результатов посещений.
- Логопед — работа с расписанием, результатами занятий и рекомендациями.
- Администратор — управление пользователями, логопедами и справочными данными.
- Основные сущности: `User`, `Patient`, `SpeechTherapist`, `Specialization`, `Appointment`, `VisitRecord`.

Пользователь связан с профилем пациента или логопеда. Запись на приём связывает пациента и специалиста, результат посещения относится к конкретному приёму. Между логопедами и специализациями предусмотрена связь многие-ко-многим.

## Лабораторная работа №1 — PostgreSQL и SQLAlchemy

Создана база данных PostgreSQL `speech_center`. Реализованы ORM-модели SQLAlchemy и связи между таблицами. Добавлены операции создания, чтения, изменения и удаления пользователей, пациентов, логопедов, специализаций, записей и результатов посещений.

- `app/database.py` — подключение к БД и настройка сессий.
- `app/models/` — ORM-модели таблиц и связи между ними.
- `app/crud/` — функции работы с данными.
- `alembic/` — миграции структуры БД.

Реализованы назначение специализаций логопедам, запись пациентов на приём и сохранение результатов занятий. Работа с БД выполняется через сессии SQLAlchemy; изменения сохраняются с помощью `commit`.

## Лабораторная работа №2 — REST API

Реализованы HTTP-маршруты для пользователей, пациентов, логопедов, специализаций, записей и результатов посещений. Данные проверяются Pydantic DTO. Доступ ограничивается ролями и принадлежностью данных.

- Регистрация: `POST /api/auth/register`.
- Вход: `POST /api/auth/login`.
- Профиль: `GET /api/users/me`.
- Основные ресурсы: `/api/therapists`, `/api/specializations`, `/api/appointments`, `/api/visit-records`.

Пароли хешируются Argon2. После входа выдаётся JWT Access Token на 60 минут; клиент передаёт его в `Authorization: Bearer <token>`. Refresh Token не используется.
Сессия БД передаётся через `Depends` и закрывается после запроса. Nginx принимает HTTP-запросы и проксирует их в Uvicorn/FastAPI.

## Лабораторная работа №3 — Взаимодействие через gRPC

Добавлен отдельный сервис подбора логопедов. FastAPI получает кандидатов из PostgreSQL и передаёт сервису нужную специализацию, ID логопедов, их специализации и стаж. Сервис фильтрует кандидатов и сортирует по убыванию стажа. FastAPI получает упорядоченные ID и возвращает данные логопедов в JSON.

Запрос: `GET /api/therapists/recommendations?specialization_id=2`.

- `services/recommendations/recommendation.proto` — контракт метода `Recommend` и сообщений.
- `services/recommendations/recommendation_pb2.py`, `services/recommendations/recommendation_pb2_grpc.py` — сгенерированный код сообщений и gRPC-взаимодействия.
- `services/recommendations/server.py` — алгоритм подбора и запуск сервера на `127.0.0.1:50051`.
- `services/recommendations/client.py` — вызов сервиса из FastAPI с тайм-аутом 5 секунд.

FastAPI и gRPC-сервис запускаются в отдельных процессах. Для демонстрации выполняется HTTP-запрос через Swagger UI или Postman; участие gRPC-сервиса видно в его консоли.
