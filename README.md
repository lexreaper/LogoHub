## Лабораторная работа №2. Разработка REST API

### 18. Назначение REST API

В рамках лабораторной работы разработан REST API для информационной системы центра логопедии на основе FastAPI.

API обеспечивает взаимодействие клиентской части приложения с базой данных PostgreSQL посредством HTTP-запросов. Обмен данными осуществляется в формате JSON.

Реализованы операции управления пользователями, логопедами, специализациями, записями на приём и результатами посещений.

### 19. Используемые технологии

| Технология | Назначение |
|---|---|
| Python | Разработка серверной логики |
| FastAPI | Реализация REST API |
| PostgreSQL | Хранение данных |
| SQLAlchemy | ORM для взаимодействия с БД |
| Pydantic | Валидация данных и DTO |
| JWT | Аутентификация и авторизация |
| Uvicorn | Запуск ASGI-приложения |
| Nginx | Обратное проксирование HTTP-запросов |

### 20. Архитектура приложения

REST API реализовано с разделением ответственности между основными компонентами.

**API-обработчики** принимают HTTP-запросы, выполняют необходимые операции и формируют ответы.

**DTO (Data Transfer Object)** используются для описания структуры входных и выходных данных. С помощью Pydantic обеспечивается проверка типов и обязательных полей.

**ORM (Object-Relational Mapping)** реализовано через SQLAlchemy и позволяет взаимодействовать с таблицами PostgreSQL посредством Python-объектов.

**Dependency Injection** применяется для передачи зависимостей обработчикам, включая сессии базы данных и информацию об авторизованном пользователе.

Общая схема взаимодействия компонентов:

`Клиент → Nginx → FastAPI → SQLAlchemy → PostgreSQL`

### 21. Реализация CRUD-операций

Для работы с данными реализованы стандартные HTTP-методы REST API.

| HTTP-метод | Операция | Назначение |
|---|---|---|
| POST | Create | Создание записи |
| GET | Read | Получение данных |
| PATCH | Update | Частичное изменение записи |
| DELETE | Delete | Удаление записи |

Примером является управление логопедами:

| Маршрут | Назначение |
|---|---|
| `POST /therapists` | Добавление логопеда |
| `GET /therapists` | Получение списка логопедов |
| `GET /therapists/{id}` | Получение логопеда по ID |
| `PATCH /therapists/{id}` | Изменение данных логопеда |
| `DELETE /therapists/{id}` | Удаление логопеда |

Для операций предусмотрены соответствующие HTTP-коды ответа, включая `200 OK`, `201 Created`, `204 No Content` и `404 Not Found`.

### 22. Регистрация и аутентификация пользователей

В системе реализованы регистрация и вход пользователей.

Основные маршруты:

- `POST /auth/register` — регистрация нового пользователя.
- `POST /auth/login` — проверка учётных данных и получение токена.
- `GET /users/me` — получение информации о текущем пользователе.

Пароли хранятся в виде хешей.

Для аутентификации используется JWT (JSON Web Token). После успешного входа пользователь получает токен доступа, который передаётся в заголовке `Authorization` при обращении к защищённым маршрутам.

### 23. Разграничение прав доступа

В приложении предусмотрены три роли:

- **Пациент** — работа с собственными данными и записями на приём.
- **Логопед** — работа с назначенными приёмами и результатами посещений.
- **Администратор** — управление логопедами и справочными данными.

Доступ к защищённым операциям определяется на основании JWT и роли пользователя.

### 24. Реализация Reverse Proxy с использованием Nginx

В рамках дополнительного задания настроен Nginx в качестве обратного прокси-сервера.

Nginx принимает HTTP-запросы на порту `8080` и перенаправляет обращения к API на FastAPI, работающий на порту `8000`.

Дополнительно реализована раздача статических файлов непосредственно через Nginx.

Таким образом, Nginx выполняет две функции:

- маршрутизация HTTP-запросов к серверному приложению;
- обслуживание статического содержимого без обращения к FastAPI.

### 25. Результаты лабораторной работы

В результате выполнения лабораторной работы разработано REST API для информационной системы центра логопедии.

Реализованы CRUD-операции, взаимодействие с PostgreSQL через ORM, использование DTO для валидации данных и Dependency Injection для управления зависимостями.

Дополнительно реализована JWT-аутентификация с разграничением прав доступа и настроен Nginx для обратного проксирования и раздачи статических файлов.

Работоспособность основных функций подтверждена тестированием HTTP-запросов через Swagger UI.
