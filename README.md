# Лабораторная работа №1

## 12. Реализация базы данных

В рамках лабораторной работы №1 была реализована база данных информационной системы центра логопедии на основе схемы, разработанной в лабораторной работе №0.

Для хранения данных используется **PostgreSQL**, а взаимодействие Python-приложения с базой данных реализовано с помощью **SQLAlchemy ORM**.

В проекте реализованы ORM-модели:

- `User`;
- `Patient`;
- `SpeechTherapist`;
- `Specialization`;
- `SpeechTherapistSpecialization`;
- `Appointment`;
- `VisitRecord`.

Модель `SpeechTherapistSpecialization` представляет промежуточную сущность для реализации отношения многие-ко-многим между логопедами и специализациями.

Подключение к PostgreSQL выполняется посредством SQLAlchemy Engine и драйвера `psycopg2`. Для выполнения операций с базой данных используются сессии SQLAlchemy.

## 13. Реализованные CRUD-операции

Для основных сущностей системы реализованы функции работы с данными.

### Пользователи

Реализованы:

- создание пользователя;
- получение пользователя по идентификатору;
- поиск пользователя по электронной почте;
- получение списка пользователей;
- изменение данных пользователя.

### Пациенты

Реализованы:

- создание профиля пациента;
- получение пациента;
- получение списка пациентов;
- изменение данных пациента.

### Логопеды

Реализованы:

- создание профиля логопеда;
- получение логопеда;
- получение списка логопедов;
- изменение информации о логопеде.

### Специализации

Реализованы:

- создание специализации;
- получение специализации;
- получение списка специализаций;
- изменение специализации;
- удаление специализации;
- назначение специализации логопеду;
- получение специализаций выбранного логопеда.

### Записи на приём

Реализованы:

- создание записи на приём;
- получение записи;
- получение списка записей;
- получение записей пациента;
- получение расписания логопеда;
- изменение данных и статуса записи.

Для исключения двойной записи одного логопеда на одинаковое время используется ограничение уникальности сочетания `speech_therapist_id` и `appointment_at`.

### Результаты посещений

Реализованы:

- создание результата посещения;
- получение результата;
- получение результата по записи на приём;
- получение списка результатов;
- изменение описания, результата и рекомендаций.

## 14. Проверка работы базы данных

Для проверки работы реализован тестовый сценарий `test_db.py`.

Перед выполнением сценария тестовые данные удаляются из таблиц. После этого последовательно проверяются основные операции приложения:

1. создание пользователей с ролями пациента, логопеда и администратора;
2. получение и изменение данных пользователей;
3. создание и изменение профиля пациента;
4. создание и изменение профиля логопеда;
5. создание специализаций;
6. назначение нескольких специализаций одному логопеду;
7. получение специализаций логопеда;
8. создание записи пациента на приём;
9. получение записей пациента;
10. получение расписания логопеда;
11. изменение статуса приёма с `scheduled` на `completed`;
12. создание результата посещения;
13. получение результата посещения;
14. изменение рекомендаций;
15. удаление тестовой специализации.

Тестовый сценарий успешно демонстрирует операции **CREATE, READ, UPDATE и DELETE**, работу отношения **многие-ко-многим**, создание записи на приём и сохранение результата посещения.

## 15. Миграции базы данных

Для управления версиями схемы базы данных в проект подключён **Alembic**.

Alembic настроен для работы с метаданными SQLAlchemy-моделей проекта. Создана начальная ревизия:

`430e66c533ca — initial schema`

Существующая схема PostgreSQL зарегистрирована как начальное состояние миграций. Это позволяет в дальнейшем изменять структуру базы данных с помощью последовательных миграций без необходимости пересоздания всей базы данных.

Основные команды:

```bash
python -m alembic current
python -m alembic history
python -m alembic revision --autogenerate -m "описание изменения"
python -m alembic upgrade head
```

## 16. Запуск и проверка лабораторной работы №1

Перед запуском необходимо установить зависимости проекта и создать базу данных PostgreSQL `speech_center`.

Для создания отсутствующих таблиц:

```bash

```

Для проверки текущей версии Alembic:

```bash

```



## 17. Результат лабораторной работы №1

В рамках лабораторной работы №1 реализован слой хранения данных информационной системы центра логопедии.

Созданы ORM-модели SQLAlchemy в соответствии со спроектированной схемой базы данных, настроено подключение к PostgreSQL и реализованы CRUD-операции для основных сущностей системы.

Реализована связь многие-ко-многим между логопедами и специализациями, обеспечена возможность создания записей пациентов на приём, изменения их статуса и сохранения результатов проведённых посещений.

Работоспособность реализованных функций подтверждена тестовым сценарием `test_db.py`. Дополнительно настроен Alembic для управления версиями схемы базы данных.
